## Summary

The host's turn done/error pushes and presence now work against real dsh event shapes. The handlers in `src/notify/dsh-events.ts` are typed against the real signatures of dsh 0.1.5-rc.3: `session/event` is emitted as `(session, event)` (session as the first argument), `agent/error` carries `{ agent, turn, step, error }` with no `sessionId` field (the failing agent's id IS the session id), and `agent/status` carries `{ agent, status }`. `turn/end` routes to `notifyTurnDone`, `agent/error` to `notifyTurnError` (error text extracted by `describeTurnError`, never logged), `agent/status` to the keep-awake manager. `isDeviceForegrounded` is no longer the constant `false`: a device counts as foregrounded on a session when it has an open channel (ChannelManager probe, unchanged) AND holds a live `sessions.follow` stream for that session, tracked by the new `FollowTracker` via a `PresenceTrackingSessionAdapter` that is the real `SessionAdapter` plus exactly one observation hook. Apply-harness tests emit events with the exact real shapes (`ctx.emit('session/event', session, event)`) using a `turn/end` taken verbatim from `test/fixtures/dsh-0.1.5-rc.3/follow-*.jsonl`.

## Deviations from the packet

- The packet's deliverable text says `turn/end` maps to `notifyTurnDone(session.id, title)`. Real dsh does not expose a session/turn title on the emitted `Session` or on the `turn/end` event, so the bridge calls `notifyTurnDone(session.id, null)` / `notifyTurnError(sessionId, errorText, null)` and the notifier renders its default titles (signatures already accept `string | null`). Title pass-through can be added when dsh exposes a title; noted as a follow-up below.

## Known limitations / follow-ups

- Turn-done/error push titles are the notifier's defaults; real dsh carries no title on these events (revisit if upstream adds one).
- Non-required CI jobs (conformance `--strict`, no-stubs) still fail with pre-existing findings; unchanged by this diff, scheduled for P7-V3.
- `isDeviceForegrounded` suppresses a push only while the follow stream is live; the abort-signal cleanup is covered by `test/notify/presence.test.ts`.
