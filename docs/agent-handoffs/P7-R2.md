# Handoff: P7-R2 — Relay loses the authentication-timeout alarm (unauthenticated sockets stay open)

- **Role:** relay
- **Agent:** ZCode worker (GLM 5.3 Flash)
- **Date:** 2026-10-02
- **Branch / PR:** `task/P7-R2-auth-timeout-alarm` / [#91](https://github.com/lottooss/remora/pull/91)
- **Commits:** `ccdf245` (red) · `a46b062` (green)

## Summary

`AccountHub`'s single Durable Object alarm now survives every path that consumes it for one of its two purposes. One new function, `rearmAlarm()`, computes the next alarm time as the minimum of (a) the earliest `connectedAt + authTimeoutMs()` over unauthenticated sockets — read from their hibernation attachments — and (b) the earliest due offline task; it deletes the alarm only when neither is pending. Both `cancelOfflineTask()` and the end of `alarm()` call it. Previously `cancelOfflineTask()` deleted the alarm whenever no offline task remained (e.g. a host reconnecting) and `alarm()` deleted it when no offline task was pending, either of which stranded an unauthenticated socket: it stayed open and hibernating indefinitely instead of being closed with `4408` after 10 s (RLY/1 §3). Wire behaviour is unchanged beyond RLY/1: close code `4408`, same `AUTH_TIMEOUT_MS` (10 s default) and `HOST_OFFLINE_ALERT_MS` (120 s default) timing.

## Red (commit `ccdf245`)

Two tests in workerd (`apps/relay/test/auth-timeout.test.ts`, new file; the real Durable Object is exercised, only FCM delivery is faked — the other side of the boundary):

1. *closes an unauthenticated socket with 4408 when an offline-task cancellation consumed the shared alarm* — a socket connects and never authenticates; a host connects/authenticates/disconnects (offline task armed) and reconnects/authenticates (`onAuth` → `cancelOfflineTask`). Running the alarm at `connectedAt + 10 s` must still close the socket with `4408`.
2. *re-arms the alarm for an unauthenticated socket when an earlier host-offline alarm fires* — the pending socket connects at `now + 10 min` (`vi.setSystemTime`), so its deadline lies far beyond the offline task's due time; the alarm fires for the task (exactly one `host_offline` FCM push captured) while the socket is not yet due, and must be re-armed for exactly `connectedAt + AUTH_TIMEOUT_MS`; running it then closes the socket with `4408`.
