## Summary

The repository now has a ground-truth boot gate: `tests/real-dsh/boot.spec.ts` installs the real pinned dsh (`upstream.lock.json#npmVersion` = `0.1.5-rc.3`) into a temporary `DSH_HOME`, installs the real built `@remora/host` through the real `dsh plugin --profile remora-e2e add <repo>/packages/host`, starts the real relay under `wrangler dev` on a free port with a random test `REMORA_ENROLL_SECRET`, boots dsh with `REMORA_RELAY_ENROLL_SECRET` in its environment, and asserts the host starts, reaches the relay, and keeps the same host id across a restart. Teardown runs in `afterAll` and throws if any dsh/node/wrangler/workerd process of the run survives, a port stays listening, or temp dirs/`.dev.vars` were not cleaned up. A dedicated non-required CI job (`real-dsh`, ubuntu-latest + windows-latest matrix) runs the suite and uploads collected dsh/relay logs as artifacts on failure. As predicted by the packet, the gate is red on current code: dsh crashes on boot with `cannot get property "typertGateway" without inject` (exit 1) — that red run is the deliverable. It turns green when P7-H1–H3 land.

## Deviations from the packet

None. Two allowed interpretations worth stating:

- Packet deliverable 1 says `dsh --profile remora-e2e --from-default-profile web --help` "(or the documented way to initialize the web template without booting)" — the harness uses `--dump-config`, which initializes the web-template profile without booting, as the packet permits.
- Packet deliverable 7 says "stop dsh (SIGTERM, then kill after 10 s)" — implemented as SIGTERM + process-group kill on POSIX; on Windows `taskkill /F /T` after the 10 s grace (no SIGTERM exists there; the tree kill covers node/workerd children). Noted in the PR Risks section.

## Known limitations / follow-ups

- The gate is red by design until P7-H1 (plugin boots through `apply()`), P7-H2 (persistent identity) and P7-H3 (`remora: relay ready`) land; the job stays non-required until P7-V3 makes it required. Its failure text is the acceptance target those tasks must turn green.
- After P7-H8 (packaging) lands, the harness should switch from `dsh plugin add <repo>/packages/host` to installing the packed tarball (note already in the packet deliverable 2).
- CI runners need npm network access to install the pinned dsh and the profile's template dependencies (noted in PR Risks).
