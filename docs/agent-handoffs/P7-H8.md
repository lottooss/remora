## Summary

The packed `@remora/host` tarball used to be uninstallable: it listed the unpublished
workspace packages `@remora/crypto`, `@remora/protocol`, `@remora/relay-link` as runtime
dependencies. The host build now produces a self-contained `lib/index.js` (tsdown bundle of
`@remora/*` + `qrcode`), the packed manifest's only runtime dependency is the published `ws`
package, the dsh peer dependencies stay external, and the tarball install is the documented
path in the README and the operations runbook.

The Integrator review on #79 found that the first pass was correct **only after a full
`pnpm run build`**: from a clean checkout the host build printed `[UNRESOLVED_IMPORT] Could not
resolve '@remora/crypto' … treating it as an external dependency`, exited 0, and the tarball
failed at import with `Cannot find package '@remora/crypto'`. The follow-up makes the host
`build` script build its workspace dependencies first, makes tsdown fail closed on any
unresolved or non-allow-listed import, and adds `packages/host/test/pack.test.ts`, which
reproduces the clean checkout in the unit-test run.

## Deviations from the packet

- `packages/host/test/pack.test.ts` is outside the packet's `owned_paths`; the orchestrator asked for it in the review follow-up.
- `tests/real-dsh/harness.ts` (protected) changed in the first pass, as the packet's deliverable asks; owner approval is still pending. The follow-up made no further edit there.
- `pnpm-lock.yaml` changed as a consequence of the `package.json` dependency moves.
- The orchestrator preferred "build workspace dependencies first AND make unresolved `@remora/*` imports a hard error"; both are implemented. Bundling the siblings from their TypeScript sources (`source` export condition) was tried and rejected: the declaration bundle then fails with `MISSING_EXPORT … ../protocol/src/index.d.ts`.
- `failOnWarn: true` needs one suppression: rolldown-plugin-dts warns that zod's `zod/v4/locales/*.d.cts` "uses CommonJS dts syntax" (63 warnings, present before this change, type declarations only). The `suppressWarnings` regex matches only that path and message; every other warning fails the build.
- `ws` stays a runtime dependency instead of being bundled (it is published; bundling it would pull its optional native peers into static resolution).
- `pnpm -F @remora/host pack` writes the tarball into the repository root with pnpm 12.6.0 (not `packages/host/`); README, runbook and harness use that path.

## Known limitations / follow-ups

- `packages/host/tsconfig.build.json` is no longer used by the host build (tsdown builds `lib/`); it is outside `owned_paths` and left in place for the Integrator.
- `pack.test.ts` needs registry access for the consumer `npm install` (`--prefer-offline` uses the npm cache when it can) and adds about 12–17 s of CPU-heavy work (install, three `tsc` builds, tsdown, npm) to `pnpm test`. It writes only to an `os.tmpdir()` directory it removes afterwards.
- `apps/relay/test/push.test.ts` > *dispatches push message … byte-identical ciphertext* failed once in CI (`expected 2 to be 1`, line 253, run 36887322615 attempt 1) while the host tests, including this pack test, ran in parallel. The test sets `HOST_OFFLINE_ALERT_MS = '100'` and its `beforeAll` closes the host socket, so a host-offline alarm that fires late lands inside the next test's capture window. That is a timing dependency in the relay test (relay role); the attempt-2 run and the green runs passed it.
