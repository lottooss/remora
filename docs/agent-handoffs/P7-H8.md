## Summary

The packed `@remora/host` tarball used to be uninstallable: it listed the unpublished
workspace packages `@remora/crypto`, `@remora/protocol`, `@remora/relay-link` as runtime
dependencies. The host build now produces a self-contained `lib/index.js` (tsdown bundle of
`@remora/*` + `qrcode`), the packed manifest's only runtime dependency is the published
`ws` package, the dsh peer dependencies stay external, and the tarball install is the
documented path in the README and the operations runbook.

## Changed paths

- `packages/host/package.json` — build via `tsdown`; `@remora/*` + `qrcode` moved to devDependencies (bundled); `ws` added as the only runtime dependency (kept external).
- `packages/host/tsdown.config.ts` — new: bundling contract (bundle `@remora/*` + `qrcode`; external `ws` + node builtins; peers auto-external).
- `packages/host/README.md` — tarball install is the documented path; "does not work yet" warning replaced with the P7-H8 packaging contract.
- `docs/runbooks/operations.md` — install step now packs the tarball and `dsh plugin add`s it.
- `tests/real-dsh/harness.ts` — **OWNER-APPROVAL-PENDING** (protected path): install the packed tarball instead of the checkout directory. Separate commit, see below.
- `docs/agent-handoffs/P7-H8.md` — this report.

## Deviations from the packet

- The packet's Verify block says `pnpm -F @remora/host pack`; note that `pnpm -F ... pack`
  writes the tarball into the **repository root** (`remora-host-1.0.0.tgz`), not into
  `packages/host/`. The README/operations/harness all use the repo-root path.
- `ws` (published, runtime dependency of the bundled `@remora/relay-link`) stays a runtime
  dependency instead of being bundled: bundling it would drag in `ws`'s optional native
  peers (`bufferutil`, `utf-8-validate`) into static resolution. The acceptance box only
  forbids `@remora/*` runtime dependencies.
