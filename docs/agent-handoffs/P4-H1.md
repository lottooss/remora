# Agent handoff: P4-H1 — Workspaces, directory browse, remote session start

## 1. What was done

- **Gateway Adapter Extensions (`packages/host/src/adapter/gateway.ts`):**
  - Mapped upstream dsh errors to RCP errors: `workspace/invalid-path` (`invalid_params`), `workspace/name-conflict` (`conflict`), `directory-picker/unavailable` (`internal_error`), `directory-picker/unreadable` (`forbidden`), `directory-picker/exists` (`conflict`), `directory-picker/create-failed` (`internal_error`).
  - Added typed wrappers: `gatewayWorkspaceFollow`, `gatewayWorkspaceCreate`, `gatewayDirectoryPickerList`, and `gatewayDirectoryPickerCreateDirectory`.

- **Workspace Adapter & RPC Methods (`packages/host/src/adapter/workspaces.ts`, `packages/host/src/rcp/methods/workspaces.ts`):**
  - Implemented `WorkspaceAdapter`:
    - `workspaces.follow`: Streams baseline, upsert, and removed increments, computing `remoteAllowed: boolean` dynamically against `PolicyGuard.checkPathAccess`.
    - `workspaces.create`: Guarded by `allowRemoteSessionStart` and roots containment. Canonicalizes path and deduplicates retries by `requestId`.
    - `workspaces.list`: Returns active workspaces with `remoteAllowed` calculated for each.
  - Registered RPC methods `workspaces.list`, `workspaces.follow`, and `workspaces.create` on `RcpServer`.

- **Filesystem Browse & Mkdir (`packages/host/src/rcp/methods/fs.ts`):**
  - Implemented `FsAdapter`:
    - `fs.browse`: Without path, lists allowlisted roots (`path: null, parent: null, entries: roots`). With path, canonicalizes, verifies containment, computes parent boundary (`null` when at root boundary to prevent escaping), and returns entries with typed kinds (`'dir' | 'file' | 'link'`).
    - `fs.mkdir`: Enforces single-segment name validation, checks parent containment and created target containment, creates folder via gateway or filesystem, handles `conflict` on collision, and deduplicates retries by `requestId`.
  - Registered RPC methods `fs.browse` and `fs.mkdir` on `RcpServer`.

- **Remote Session Creation (`packages/host/src/adapter/sessions.ts`, `packages/host/src/rcp/methods/sessions.ts`):**
  - Implemented `sessions.create`:
    - Guarded by `allowRemoteSessionStart`.
    - When `{ workspace: { path } }` is passed: implies workspace creation inside allowlisted roots.
    - When `{ workspace: { id } }` is passed: allows starting session in a pre-existing workspace created at the PC even if outside roots (per RCP/1 §6).
    - Idempotent by `requestId`.
  - Registered `sessions.create` RPC method on `RcpServer`.

- **Host Wiring (`packages/host/src/index.ts`):**
  - Exported workspace, fs, and session creation interfaces.
  - Automatically wires `WorkspaceAdapter`, `FsAdapter`, and `SessionAdapter` inside `apply(ctx, config)` when `ctx.typertGateway` is available.

- **Automated Tests:**
  - `packages/host/test/workspaces.test.ts` (14 unit tests):
    - Workspace creation inside/outside roots.
    - `allowRemoteSessionStart: false` enforcement.
    - `workspaces.follow` stream with `remoteAllowed` flags.
    - `fs.browse` roots listing and directory listing with parent calculation.
    - `fs.mkdir` single-segment validation, idempotency, and conflict handling.
    - `sessions.create` with path (guarded) and with existing outside-root ID.
    - Full end-to-end RCP message dispatch through `RcpServer`.
  - `tests/e2e/workspaces.spec.ts`:
    - E2E flow: FakeDevice connects over secure channel, browses roots, creates a directory, starts a session in that directory, prompts it, and verifies workspace list.
