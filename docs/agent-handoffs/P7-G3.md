## Deviations from the packet

None functionally; three documented interpretations:

- `globalThis.koffi` is matched as "a line containing both `globalThis` and `koffi`" because the real occurrence on main is `(globalThis as unknown as { koffi?: … }).koffi` (packages/host/src/platform/keep-awake-win32.ts:17) — the literal `globalThis.koffi` never appears in source. The fixture covers both shapes.
- `apps/relay/src/**` and `apps/cli/src/**` are scanned as TS-family files (`.ts/.mts/.cts/.tsx`); the packet writes `**` but those roots' non-source assets are not production code. `packages/*/src/**/*.ts` and `apps/android/**/src/main/**/*.kt` follow the packet literally.
- The `test` script line in `package.json` was extended from `pnpm -r run test` to `pnpm -r run test && vitest run --config scripts/vitest.config.ts` so the scanner's unit tests execute under the standard gate (per the Integrator note) — `pnpm -r` does not include the root project, and the packet's owned_paths cover `package.json`. The wave-0 additions (`test:real-dsh`, `conformance:check`) are untouched, as is every existing script.

## Known limitations / follow-ups

- The gate stays red-by-outcome (non-required) until the stub-fixing packets land and P7-V3 flips it; its findings list is the acceptance target for those packets. A finding may be suppressed only via an owner-approved allowlist entry with a reason and expiry — never by editing the scanner's patterns.
- Allowlist `file` matching is exact repo-relative path (forward slashes), `pattern` must be one of the nine names; this is documented in the scanner header and the owner copies paths straight from the scan output.
- CI's `no-stubs` job runs without `pnpm install` (dependency-free scanner), so it completes in ~25 s.
