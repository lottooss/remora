## Summary

Implemented [blueprint §8.10](../blueprint.md#810-notifications), RCP/1 §10, and Crypto/1 §8:
Turns dsh and AnswerBridge activity into timely, deduplicated, end-to-end encrypted push notifications per device, respecting preferences and presence.

Key components:
1. **Preferences Domain & RCP Methods (`packages/host/src/notify/prefs.ts`, `packages/host/src/rcp/methods/notify.ts`):**
   - `NotifyPrefsStore` interface and `InMemoryNotifyPrefsStore` persisting per-device notification preferences (`approval`, `question`, `turnDone`, `turnError`).
   - `notify.prefs.get` and `notify.prefs.set` RCP methods matching schemas in `@remora/protocol`.
2. **Payload Construction & Redaction (`packages/host/src/notify/payload.ts`):**
   - `buildPushPayload` with single-line whitespace flattening, 80-character title and body capping, secret scrubbing (PEM keys, JWTs, GitHub/AWS/Slack tokens, passwords), and hard 2,048-byte plaintext budget.
   - `sealPush` encrypting payload under device push key using `@remora/crypto`'s `sealPushPayload` (ChaCha20-Poly1305 with random 12-byte nonce prepended) encoded as base64url.
3. **HostNotifier Orchestration (`packages/host/src/notify/notifier.ts`):**
   - Layered suppression: host config (`notify.approval/question/turnDone/turnError`) -> per-device preferences -> presence (`isDeviceConnected` + `isDeviceForegrounded`).
   - Push key validation: strictly requires 32-byte pushKey (skips non-matching or revoked devices).
   - Session access tracking: devices accessing a session within 24h are tracked as audience for `turn_done` and `turn_error`.
   - Rate limiting: turn notifications capped at <= 1 per session per 30 s.
   - Collapse keys: `pending:<id>` for approvals/questions, `session:<id>` for turns.
   - Per-device dispatch isolation: one device's failure does not block others.
4. **Cordis Plugin & AnswerBridge Integration (`packages/host/src/index.ts`, `packages/host/src/relay/index.ts`):**
   - `HostRelayConnection.sendPushFrame` sending RLY/1 `push` control frames to the relay.
   - Session access hook wired into `registerSessionMethods`.
   - Automatic subscription to `PendingRegistry` deltas (`approval` and `question` requests).
   - Event listeners for `session/event` (`turn/end`) and `agent/error`.
   - Proper lifecycle disposal via `ctx.effect`.
5. **Comprehensive Test Suite (`packages/host/test/notify.test.ts`):**
   - Verified preference defaults and updates via RCP server dispatch.
   - Verified approval and question notifications with full `@remora/crypto` `openPushPayload` round-trip decryption.
   - Verified presence-aware suppression when connected and foregrounded.
   - Verified suppression when preferences or host configuration disable a kind.
   - Verified session audience tracking and 30s turn throttling.
   - Verified secret scrubbing, string truncation, and lifecycle detachment.
