## Summary

Added a `--strict` mode to `scripts/check-conformance.mjs` and the non-required CI job `conformance-strict` that runs it. Strict mode fails a vector file when any case is a placeholder (`input.status === "scaffold"`, or a name matching `/placeholder|scaffold/i`), when the file is below the per-area case minimums from the packet (crypto ≥ 3 cases incl. ≥ 1 error, Cacophony exempt; `rcp/methods/*` ≥ 2 valid + ≥ 1 invalid; `rcp/envelope.json`, `rcp/limits.json`, `rcp/session-events.json`, `relay/*` ≥ 5 cases incl. ≥ 1 error), or when it lives in an unknown vector area (so the gate never silently skips a file). It prints a per-file summary and a total count of violations. Non-strict behavior and output are unchanged. The CI job has `continue-on-error: true` (per the packet; P7-V3 removes it), so the overall run stays green while the strict job's log shows the failure until wave 4 fills the vectors.

## Deviations from the packet

- Added rule beyond the packet text: files in an unknown vector area are strict violations (`unknown vector area: no strict minimum defined`). Rationale: a strict gate that silently skips unclassifiable files would be fail-open; a new top-level area is a contract change anyway (conformance/README.md layout). The Cacophony exemption is implemented by exact relative path `crypto/noise-cacophony-ikpsk2.json`.
- The strict job runs `pnpm run conformance:check -- --strict` without `pnpm install`: the checker is dependency-free (node:fs/node:path only), so the job is checkout + node + the Verify command. No behavioral difference.
