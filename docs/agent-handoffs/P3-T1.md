# Agent handoff: P3-T1 — Security test suite (threat model §5)

## 1. What was done

- **Automated Security Test Suite (`tests/security/`):**
  - Configured `tests/security/vitest.config.ts` running with path aliases, 60s timeouts, and `maxWorkers: 1` for serial execution without port collision.
  - Added npm script `"test:security": "vitest run --config tests/security/vitest.config.ts"` in root `package.json`.
  - **`path-escapes.spec.ts` (11 tests):**
    - Path traversal (`..`) escaping configured root rejected.
    - Absolute path outside roots rejected.
    - Windows directory junction (`mklink /J`) escaping root rejected.
    - Symlink escaping root rejected.
    - UNC paths (`\\server\share`) rejected.
    - Device namespace paths (`\\?\`, `\\.\`) rejected.
    - Alternate Data Streams (NTFS `:stream`) rejected.
    - Trailing dots and spaces on Windows canonicalized and confined.
    - 8.3 short name resolution canonicalized and confined.
    - Embedded NUL bytes rejected.
    - Path inside valid root allowed.
  - **`limits-and-revocation.spec.ts` (5 tests):**
    - RCP messages exceeding 48 KiB limit rejected with `too_large`.
    - Per-device burst rate limit (>20 requests/sec) throttled with `rate_limited`.
    - Mutating request rate limit (>5 mutating requests/sec) throttled with `rate_limited`.
    - Max concurrent open streams per device capped at 10.
    - Device revocation immediately disconnects channels, clears sessions, and denies subsequent requests.
  - **`log-scans.spec.ts` (3 tests):**
    - Static analysis across `packages/host/src` verifies zero use of `console.*` (enforcing `ctx.logger`).
    - Relay data frame handling verified to parse only 28-byte RLY/1 headers without accessing, buffering, or logging payload bytes.
    - Comprehensive scan across mock logs and memory buffers asserts zero raw secrets (Noise private keys, PSKs, enrollment tickets, push keys) and verifies endpoint/channel IDs are truncated to <= 6 characters.
  - **`approvals.spec.ts` (7 tests):**
    - High-risk approval without signature rejected by Policy Guard (`signature_required`).
    - High-risk approval with forged signature rejected (`invalid_signature`).
    - Android Keystore P-256 high-S DER signatures accepted (`lowS: false` per Crypto/1 §7).
    - `argsDigest` mismatch rejected (`args_digest_mismatch`).
    - Replay of single-use approval answer rejected (`already_resolved`).
    - Answer submitted for another session rejected.
    - Answers rejected after device revocation.
  - **`pairing-attacks.spec.ts` (4 tests):**
    - Pairing without PC operator SAS confirmation rejected and device omitted from registry.
    - Incorrect SAS code confirmation fails and denies admission.
    - Enrollment ticket reuse rejected with 410.
    - Substituted host static key in QR payload rejected.
  - **`adversarial-relay.spec.ts` (7 tests):**
    - 1-bit flip in transport ciphertext causes immediate session closure, zero plaintext processed.
    - Replay of duplicate transport record rejected (Noise duplicate nonce failure) and channel closed.
    - Frame splicing (tampered ciphertext) fails MAC and closes channel.
    - Unknown/unallowlisted device static key silently denied admission without host response.
    - Wrong PSK fails Noise IKpsk2 tag verification and closes channel.
    - Substituted responder key fails handshake.
    - E2E test with `AdversaryRelayProxy` intercepting live relay traffic: bit-flipped frame in transit triggers host channel teardown.
- **Threat Model Specification (`docs/specs/threat-model.md`):**
  - Updated §3 threat mitigation table: linked every applicable threat (T01–T07, T09–T16, T18–T28) to automated test suites with PASS status.
  - Updated §5 security test checklist to check all verified automated test categories.
