## Summary

Implemented [RLY/1 §8](../specs/relay-v1.md#8-push) and §5: FCM HTTP v1 push dispatch for host-provided ciphertext, device FCM push token registration with `hostOffline` preference, token cleanup upon invalidation, and Durable Object host-offline alarms.

Key components:
1. **FCM HTTP v1 Client & RS256 OAuth Minter (`apps/relay/src/fcm.ts`):**
   - Mints OAuth2 access tokens from `FCM_SERVICE_ACCOUNT_JSON` using WebCrypto (`RSASSA-PKCS1-v1_5` + SHA-256) per RFC 7523 without Node.js dependencies (`workerd` compatible).
   - In-memory token caching with safety skew (expires 5 min before nominal TTL).
   - Full fail-closed error handling and configurable `FCM_ENDPOINT` / `FCM_TOKEN_ENDPOINT` overrides.
   - `sendFcmDataMessage` dispatching data-only FCM messages `{ v: "1", h: "<hostId>", ct: "<ct>" }` with `collapse_key`, `priority`, and `ttl`.
2. **AccountHub Push & Alarm Routing (`apps/relay/src/account-hub.ts`):**
   - Forward SQLite migration in `init()` for `host_offline` preference column on `endpoints`.
   - `push.token` handling persisting device FCM token and `hostOffline` preference.
   - `push` handling enforcing host authentication, bounded `ct` (≤ 3072 characters), linked peer verification, and byte-identical forwarding (relay never decrypts or inspects `ct`).
   - Token cleanup: removes `fcm_token` in SQLite on `UNREGISTERED` or `INVALID_ARGUMENT` and reports `unregistered` status.
   - Host-offline alert: on host's last socket close, arms Durable Object alarm (`HOST_OFFLINE_ALERT_MS`, default 120s); if the host remains offline when the alarm fires, dispatches metadata-only push `{ v: "1", h: "<hostId>", k: "host_offline" }` to opted-in linked devices; cancels alarm on host reconnection.
3. **Comprehensive Test Suite (`apps/relay/test/push.test.ts`):**
   - In-memory fake FCM server verifying token registration, push fan-out, byte-identical `ct` preservation, error mapping, token cleanup, alarm arming/cancellation, and host-offline push alerts.
