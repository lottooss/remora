## Summary

`enrollHost()` existed but nothing in production called it, so the real host was unknown to the
relay and every connection died with close 4403. The plugin now enrolls before it dials: the
secret named by `config.enrollSecretKey` is resolved through the dsh credentials seam (launch
env → store → project `.env` → `$DSH_HOME/.env`), `POST /v1/enroll/host` is sent with the host's
relay public key, and the success is remembered in the dsh credentials record
`remora/relay-enrollment` (host id + relay origin) so later starts skip the request. Network,
429, and 5xx failures retry with a doubling, capped, abort-aware backoff; `401` and other final
answers are logged once with an actionable message and the relay loop is never started. With
this change the `real-dsh` gate is fully green (2/2 on ubuntu-latest and windows-latest).

## Review checklist (from the PR handoff note) — all verified in the diff

1. Enrolled-origin flag persisted: record `remora/relay-enrollment` `{ hostId, enrolledRelayOrigin }`
   (`enrollment.ts`); `isEnrolledWith()` matches both exactly; cleared by `forgetRelayEnrollment()`
   when the relay ends the link for good (status `idle` after 4401/4403/4409).
2. Missing secret: `resolveEnrollSecret` throws `RemoraConfigError` naming `config.enrollSecretKey`
   and where to put it; validated once at load and re-resolved per attempt.
3. 401 path: non-retryable `unauthorized` `RelayEnrollmentError`; apply harness asserts the
   relay link is never started.
4. Retry with backoff: doubling delay capped at `DEFAULT_ENROLL_MAX_RETRY_DELAY_MS`, abort-aware
   waits, retryable = network / 429 / 5xx only.
5. `remora: relay ready (host <first 6 chars>)` logged at info on `ready`.
6. Secret never logged: it exists only in the `Authorization` header; error messages carry the
   error code or status (pattern-gated), never the value.

## Deviations from the packet

- The remembered enrollment is additionally **cleared when the relay ends the link for good**
  (status `idle`), so a relay that lost its endpoint table does not refuse this host forever.
  Beyond the letter of the packet, in its spirit (idempotent, self-healing enrollment).
- The secret is re-resolved for every attempt (the seam's per-operation contract) rather than
  resolved once — stricter than the packet text.
- Commit `01fd3f2` was committed as-saved when the worker's machine shut down; it was reviewed
  item-by-item against the packet before this handoff (no changes were needed).

## Known limitations / follow-ups

- Enrollment runs in the background so the management page is up while an unreachable relay is
  retried; a final failure is logged once. The relay loop simply never starts in that case —
  by design (fail closed).
- The `real-dsh` gate is green from this merge onward (SWARM.md §5): every later PR must keep
  it green; a red `real-dsh` run blocks the merge.
