# Agent handoff: P3-K1 — Android approvals, questions, biometric signing, app lock

## 1. What was done

- **Data & Domain Layer (`:core:data`):**
  - Implemented `InteractionModels.kt` (`PendingApproval`, `PendingQuestion`, `QuestionOption`, `PendingInteraction`, `ResolvedNotice`).
  - Implemented `InteractionRepository.kt` with thread-safe in-memory state flows (`allPending`, `getPendingForSession`, `resolvedEvents` with `replay = 1`).
  - Implemented `InteractionService.kt`:
    - `answerApproval`: validates preview text digest against displayed content bytes (refuses with `SecurityException` on mismatch, threat model T14), prompts for biometric signature on high-risk approvals via `buildCanonicalApprovalMessage` and P-256 ECDSA, submits `approvals.answer` RPC.
    - `answerQuestion`: formats answers or text, submits `questions.answer` RPC.
    - `rotateApprovalKeyOnHost`: generates new P-256 SPKI DER public key and submits `devices.rotateApprovalKey` RPC (Crypto/1 §10).
  - Unit tested in `InteractionTest.kt`:
    - High-risk approvals require biometric signatures and fail closed without provider.
    - Normal-risk approvals require only unlocked app and emit no `sig`.
    - Digest mismatch test verifies that tampered displayed preview blocks signing before invoking key.
    - Question answers dispatch RPC.
    - Resolution events properly update flow and remove items.

- **Conversation & Approvals UI (`:feature:conversation`):**
  - Implemented `ApprovalsScreen.kt`: Cross-host approvals inbox with full horizontally scrollable monospace preview (never silently truncated), risk badges (`HIGH RISK` vs `NORMAL`), expiry countdown timer, and Approve / Reject actions.
  - Implemented `InteractionTakeover.kt`:
    - `ApprovalTakeoverCard`: Inline takeover in conversation screen with monospace code blocks, risk chip, countdown, and direct Approve/Reject.
    - `QuestionTakeoverCard`: Free text inputs, option chips (single & multi-select), and plan review presentation with markdown detail.
  - Integrated into `ConversationScreen.kt` with snackbar notifications for items resolved elsewhere (e.g. by PC).
  - Tested in `ApprovalsTest.kt`.

- **Security & Settings UI (`:feature:settings`):**
  - Updated `SettingsScreen.kt`:
    - `FLAG_SECURE` window protection toggle (prevents screenshots / task switcher leaks).
    - App lock toggle (enforces biometric/PIN prompt on cold start or > 5 min background).
    - Biometric approval key status indicator.
    - Device approval key rotation action.

- **Host Alignment (`packages/host`):**
  - Unified `PolicyGuard` interface between `packages/host/src/policy/index.ts` and `src/interaction/**`.
  - Updated `registerInteractionMethods` in `packages/host/src/rcp/methods/interaction.ts` to pass full verification context to `PolicyGuard.verifyApprovalSignature`.
  - Fixed verbatimModuleSyntax and exactOptionalPropertyTypes in `packages/host/src/policy/**`.
