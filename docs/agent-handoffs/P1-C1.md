## Summary

Implemented complete `@remora/crypto` production suite adhering strictly to [Crypto/1](../../docs/specs/crypto-v1.md):
1. **Noise IKpsk2:** Full `Noise_IKpsk2_25519_ChaChaPoly_SHA256` implementation (`CipherState`, `SymmetricState`, `HandshakeState`) using `@noble/curves` and `@noble/ciphers`. Supports Remora handshake prologues, PSK derivation, and passes all official Cacophony test vectors.
2. **Endpoint IDs:** Deterministic derivation of `h_...` and `d_...` endpoint IDs via `prefix + base32(SHA-256("remora/1 endpoint-id" || 0x00 || relayPub)[0..16])`.
3. **Relay Auth:** Ed25519 challenge signing and verification over `"remora/1 relay-auth\x00" + challengeToken`.
4. **Pairing & SAS:** QR payload encoding/decoding (`remora://pair?v=1&...`), `pairPsk` derivation with HKDF-SHA256, and 6-digit numeric SAS code generation.
5. **Approval Signatures:** Canonical approval message formatting, canonical JSON hashing for `argsDigest`, and ECDSA P-256 DER signature verification using `@noble/curves/p256` with `lowS: false` and `prehash: true` (empirically accepting Android Keystore high-S signatures).
6. **Push Payload AEAD:** ChaCha20-Poly1305 push payload sealing and opening with random 12-byte nonces.
7. **Encoding Utilities:** Base32 and unpadded Base64url (failing closed and rejecting `=` padding characters).
8. **Vector Generator:** Created `packages/crypto/scripts/gen-vectors.ts` producing deterministic conformance test vectors across all cryptographic primitives.
