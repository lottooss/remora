# Spike Findings: P0-S6 — Windows Always-On Host Without Admin + Keep-Awake

> **Task:** P0-S6  
> **Status:** Complete  
> **Platform:** Windows 10 / 11 (Standard User, Non-Elevated)  
> **Directory:** `spikes/p0-s6-always-on/`

---

## 1. Executive Summary

Spike P0-S6 investigated and validated the Windows host operating mechanisms for [ADR-0009](../../docs/adr/0009-always-on-host.md) and [blueprint §8.11](../../docs/blueprint.md#811-keep-awake):
1. **Per-User Logon Start (Non-Elevated):** Evaluated Task Scheduler, `HKCU\...\Run`, and per-user Startup folder without administrator rights. Both Task Scheduler (`Register-ScheduledTask`) and `HKCU Run` succeed without elevation.
2. **Windowless Execution:** Evaluated window suppression techniques. `conhost.exe --headless` (built into modern Windows) reliably runs CLI processes without console windows or visual flashes.
3. **Keep-Awake (`SetThreadExecutionState`):** Successfully invoked `kernel32.dll` `SetThreadExecutionState` with `ES_CONTINUOUS | ES_SYSTEM_REQUIRED` (`0x80000001`) both in-process via `koffi` and via an out-of-process helper. Neither requires elevation.
4. **Resolution to Q9:** Determined the trade-offs between in-process `koffi` and an external helper process. In-process `koffi` is recommended for primary execution due to zero IPC overhead and automatic OS cleanup on process termination.

## 2. Logon Autostart Methods Matrix

| Method | Needs Admin? | Window Flash? | Restart on Failure? | Runs After Sleep/Resume? | Evaluation & Recommendation |
|---|---|---|---|---|---|
| **Task Scheduler (`Register-ScheduledTask`)** | **No** (per-user trigger) | None (if launched via `conhost --headless`) | Yes (`RestartInterval`, `RestartCount`) | Yes (remains active across sleep/wake) | **Recommended (Primary):** Provides native restart-on-crash supervision and clean per-user management without elevation. |
| **`HKCU\...\Run` Key** | **No** | None (if launched via `conhost --headless`) | No (requires custom supervisor) | Yes | **Recommended (Fallback):** Ultra-simple fallback if task scheduling is restricted by enterprise policy. |
| **Per-User Startup Folder** | **No** | None (if shortcut configured minimized/hidden) | No | Yes | Usable, but less declarative than registry or task scheduler. |
| **Windows Service** | **Yes** (Admin required) | None | Yes | Yes | **Rejected:** Violates ADR-0009 non-admin constraint; runs in separate Session 0 isolated from user profile. |

### 2.1 Window Suppression: `conhost.exe --headless`
Traditional techniques (`wscript.exe` running a VBS wrapper, or `powershell -WindowStyle Hidden`) cause a brief, noticeable black console flash during logon.  
Modern Windows 10 (21H2+) and Windows 11 include `conhost.exe --headless <command>`, which spawns console executables completely detached from any desktop window:
```text
conhost.exe --headless node.exe "%LOCALAPPDATA%\Remora\bin\remora-supervisor.mjs"
```
Tested and confirmed zero window flash during startup.

## 3. Keep-Awake Mechanics (Q9)

### 3.1 Win32 API Contract
`kernel32.dll!SetThreadExecutionState` controls system sleep behavior:
- `ES_SYSTEM_REQUIRED` (`0x00000001`): Informs the power manager that the system is in use, preventing idle transition to sleep.
- `ES_CONTINUOUS` (`0x80000000`): Informs the power manager that the state being set should remain in effect until the next call that uses `ES_CONTINUOUS` and clears the other flags.
- **Display Sleep:** Note that `ES_DISPLAY_REQUIRED` is **not** set; monitors are permitted to turn off to preserve power and privacy.

### 3.2 In-Process (`koffi`) vs External Helper
We tested both implementations in `spikes/p0-s6-always-on/`:
1. **In-Process (`keep-awake.mjs` via `koffi`):**
   - **Pros:** Sub-millisecond call, zero process overhead, directly managed by Cordis plugin lifecycle.
   - **Crucial Win32 Invariant:** Thread execution states are associated with the calling thread and process. If the host process exits or crashes, the Windows kernel **automatically releases** the execution state, avoiding permanent sleep blocking.
   - **Packaging:** `koffi` bundles prebuilt native binaries for `win32-x64` and `win32-arm64`. When installed via npm or bundled into the packed tarball, it resolves seamlessly.
2. **External Helper (`helper-keep-awake.ps1` via P/Invoke):**
   - **Pros:** Zero native npm dependency.
   - **Cons:** ~300–800 ms PowerShell invocation latency, requires PID tracking, and risks orphan processes holding sleep locks if the parent crashes ungracefully.

**Conclusion for Q9:** `koffi` is resolvable and safe to use in-process within the host bundle. It should be the default for Windows keep-awake.

### 3.3 Powercfg Observation
Calling `SetThreadExecutionState` succeeds without elevation in user mode (returns previous state `0x80000000`).  
However, inspecting system power requests via `powercfg /requests` requires administrator privileges on modern Windows builds. When running as a standard user, `powercfg` reports:
```text
This command requires administrator privileges and must be executed from an elevated command prompt.
```
Therefore, tests and runtime health checks must not rely on `powercfg /requests` for non-elevated assertions.

## 4. Runbook Guidance for Host Owners

`SetThreadExecutionState(ES_SYSTEM_REQUIRED)` prevents **idle** sleep (e.g. timeout expiration while dsh agents are running tasks). It does **not** override hardware power triggers:
1. **Lid Close:** If running on a laptop, Windows by default sleeps when the lid is closed. Owners must configure:
   - Windows Settings → Power & Battery → "When I close the lid: Do nothing" (when plugged in).
2. **Modern Standby / Connected Standby:** On Modern Standby laptops, Wi-Fi connectivity during sleep depends on Windows networking policies. The host should be connected to AC power.
3. **Session State:** The host runs in the logged-on user session. The PC can be **locked** (`Win + L`) without interrupting dsh or Remora, but **signing out** terminates the session.
