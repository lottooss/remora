## 3. Pitfalls & Engineering Nuances Discovered

### 1. 12-Byte Nonce Encoding
- **Issue:** ChaCha20-Poly1305 (RFC 8439) uses a 12-byte (96-bit) nonce. Noise specification §5.1 specifies an 8-byte unsigned integer $n$ encoded into a 12-byte sequence.
- **Resolution:** In Remora, $n$ is encoded as 4 bytes of `0x00` followed by 8 bytes of $n$ in Little-Endian byte order. Both TS (`noiseNonce`) and Kotlin match this exact layout.

### 2. IKpsk2 PSK Placement
- **Issue:** The `psk2` modifier places the `psk` token at the end of the second message:
  - Msg 1: `-> e, es, s, ss`
  - Msg 2: `<- e, ee, se, psk`
- **Resolution:** When processing `psk`, `SymmetricState` must execute `mixKeyAndHash(psk)` (HKDF with 3 outputs: next $ck$, temp $h$, and temp $k$), updating both cipher key and running handshake hash before encrypting the message 2 payload.

### 3. Empty Payload Handling
- Handshake messages carrying 0-byte payloads produce a 16-byte Poly1305 authentication tag. Decrypting 16 bytes yields an empty `Uint8Array(0)` / `ByteArray(0)`.

## 4. API Sketch for `@remora/crypto` and `:core:crypto`

### TypeScript (`@remora/crypto`)
```ts
export class SecureChannel {
  static createInitiator(opts: SecureChannelOptions): SecureChannel
  static createResponder(opts: SecureChannelOptions): SecureChannel
  writeHandshake(payload?: Uint8Array): Uint8Array
  readHandshake(message: Uint8Array): Uint8Array
  isEstablished(): boolean
  encrypt(plaintext: Uint8Array): Uint8Array
  decrypt(ciphertext: Uint8Array): Uint8Array
}
```

### Kotlin (`:core:crypto`)
```kotlin
class SecureChannel private constructor(val role: Role) {
    fun writeHandshake(payload: ByteArray = ByteArray(0)): ByteArray
    fun readHandshake(message: ByteArray): ByteArray
    val isEstablished: Boolean
    fun encrypt(plaintext: ByteArray): ByteArray
    fun decrypt(ciphertext: ByteArray): ByteArray
}
```
