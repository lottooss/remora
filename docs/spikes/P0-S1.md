# Spike Findings: P0-S1 — dsh In-Process Adapter from an Out-of-Tree Bundle

> **Task:** P0-S1  
> **Status:** Complete  
> **Target Baseline:** `@deepseek-ai/dsh@0.1.5-rc.3` (git tag `dsh-v0.1.5-rc.3`, commit `a4c74a91e0`)  
> **Environment:** Windows 11, Node.js v24+, pnpm v10+

---

## 1. Executive Summary

Spike P0-S1 verified that an out-of-tree Cordis bundle (`packages/host` or `spikes/p0-s1-dsh-adapter`) loaded via `dsh plugin --profile remora-dev add <path>` can:
1. Call `ctx.typertGateway.invoke` and `ctx.typertGateway.stream` using strict descriptors across all needed namespaces (`session`, `workspace`, `directoryPicker`, `workspaceFiles`).
2. Consume `session/follow` streams from an initial snapshot through durable events, live assistant frames, and resumption from cursor (`afterSeq`).
3. Register exact Connection Fetch routes (`GET /api/remora/ping`) under `ctx.connection` that inherit browser authentication.
4. Read and write owner-scoped records in `ctx.credentials` and isolated documents in `ctx.storage.domain`.
5. Resolve peer dependencies cleanly when installed via a packed tarball (`pnpm -F @remora/host pack`).

## 2. Answers to Open Questions

### Q1: Can an out-of-tree plugin in an npm-installed dsh call `typertGateway.invoke/stream` with strict descriptors for `session/*`, `workspace/*`, `directoryPicker/*`, `workspaceFiles/*`?
**Verdict:** **YES.**  
**Evidence:**  
- `ctx.typertGateway` is exported as a core Cordis service by `@deepseek-ai/dsh-api-gateway`.
- Out-of-tree plugins declare `inject = ['typertGateway']`.
- Calls to `ctx.typertGateway.invoke({ namespace, method, args, signal })` pass internal descriptor validation. Arguments are validated against the Remote API schemas.
- Methods tested and verified:
  - `session.list`: Returns `{ items: SessionListItem[] }`.
  - `session.create`: Successfully creates an isolated session under a workspace.
  - `session.prompt`: Idempotently dispatches user messages; retries with identical `requestId` return the original acceptance.
  - `session.follow`: Successfully streams async iterable frames.
  - `directoryPicker.list`: Returns `{ entries: DirectoryPickerEntry[] }`.
  - `workspace.create`: Initializes workspace at specified path.

### Q2: Exact `SessionFollowRequest` fields and `SessionFollowFrame` variants; recorded fixtures
**Verdict:** **YES (documented and recorded in fixtures).**  
**Evidence:**  
- `SessionFollowRequest` schema:
  ```ts
  interface SessionFollowRequest {
    address: { kind: 'session'; sessionId: string }
    assistantStream?: boolean
  }
  ```
- **Resumption Behavior:** Notice that `SessionFollowRequest` on the wire does not take `afterSeq`. The gateway stream always begins with a `type: 'snapshot'` frame containing `{ cursor: number, records: EventRecord[], hasMore: boolean }`. The adapter implements resume client-side by maintaining `lastCommittedSeq` and discarding any initial frames where `event.seq <= afterSeq`.
- **Frame Variants Observed:**
  1. `snapshot`: Initial state baseline (`cursor`, `records`, `hasMore`).
  2. `event`: Durable session facts (`turn/start`, `message`, `tool/call`, `tool/result`, `turn/end`).
  3. `assistant-stream`: Ephemeral live assistant tokens (`delta`, `end` with `outcome: { kind: 'committed' }`).
- Fixtures recorded under `packages/host/test/fixtures/dsh-0.1.5-rc.3/`:
  - `list.json`
  - `prompt-duplicate.json`
  - `follow-opening.jsonl`
  - `follow-live.jsonl`
  - `follow-resume.jsonl`

### Q3: Can an out-of-tree plugin register exact `/api/remora/*` Fetch routes that inherit browser authentication?
**Verdict:** **YES.**  
**Evidence:**  
- `ctx.connection` (from `@deepseek-ai/dsh-client-connection`) provides route registration for the internal loopback HTTP server.
- Out-of-tree plugins inject `connection` and register exact routes:
  ```ts
  ctx.connection.registerFetchRoute('GET', '/api/remora/ping', async (req) => {
    return new Response(JSON.stringify({ ok: true, version: '1.0.0' }), {
      headers: { 'Content-Type': 'application/json' },
    })
  })
  ```
- Because `/api/*` is behind the connection middleware, browser cookie validation (`client-connection/browser-session`) is executed prior to dispatching to the registered fetch route. Requests without the signed cookie or with invalid Origin/Host headers are rejected with 401/403.

### Q4: `ctx.credentials` record API and `ctx.storage.domain` API for an out-of-tree owner
**Verdict:** **YES.**  
**Evidence:**  
- `ctx.credentials`:
  - Keys are namespaced as `${scope}/${id}` (e.g. `remora/host_identity`, `remora/devices`).
  - Methods `modifyRecord(key, updater)`, `readRecord(key)`, and `deleteRecord(key)` function without requiring internal package compilation.
- `ctx.storage.domain` (or `ctx.storageDomain`):
  - Provides SQLite-backed structured document tables defined by a schema.
  - Can be defined using standard Zod schemas or Schemastery types.

### Q10: Install form: linked checkout vs packed tarball
**Verdict:** **Packed tarball (`pnpm pack`) is the recommended production form; linked checkout is supported for dev with caveats.**  
**Evidence:**  
- When using `dsh plugin add ./packages/host` (symlink / local path), Node module resolution walks parent directories up to `c:\Users\...\ds\node_modules`. If `@deepseek-ai/cordis` or `@deepseek-ai/schemastery` exist in the monorepo root, Node may instantiate duplicate module instances, breaking Cordis Symbol / Context brand checks and Schemastery type checks.
- When using a packed tarball (`dsh plugin add ./packages/host/remora-host-1.0.0.tgz`), all dependencies resolve strictly from the dsh profile's hoisted `node_modules`, guaranteeing singletons for `@deepseek-ai/cordis` and `@deepseek-ai/schemastery`.

## 3. TypeScript Wire Types for Blueprint Seams

```ts
export interface DshSessionListItem {
  sessionId: string
  workspaceId: string
  title: string
  model: string
  createdAt: string
  updatedAt: string
  lastMessageSeq: number
  status: 'idle' | 'busy' | 'error'
}

export interface DshPromptRequest {
  requestId: string
  sessionId: string
  mode: 'queue' | 'steer'
  content: Array<{ type: 'text'; text: string } | { type: 'attachment'; id: string }>
}

export interface DshPromptResponse {
  accepted: boolean
  requestId: string
  sessionId: string
  messageId: string
  seq: number
}

export type DshFollowFrame =
  | { type: 'snapshot'; cursor: number; records: DshEventRecord[]; hasMore: boolean }
  | { type: 'event'; event: DshEventRecord }
  | { type: 'assistant-stream'; frame: DshAssistantFrame }

export interface DshEventRecord {
  seq: number
  type: 'turn/start' | 'message' | 'tool/call' | 'tool/result' | 'turn/end'
  turnId?: string
  role?: 'user' | 'assistant'
  content?: Array<{ type: 'text'; text: string }>
  callId?: string
  toolName?: string
  args?: Record<string, unknown>
  result?: unknown
  timestamp: string
}

export type DshAssistantFrame =
  | { type: 'delta'; text: string }
  | { type: 'end'; outcome: { kind: 'committed' | 'aborted' } }
```

## 4. Recommended Adapter Architecture

`packages/host/src/adapter/dsh-adapter.ts`:
1. **Encapsulation:** All `ctx.typertGateway` calls, error mapping, and stream subscriptions stay isolated within `packages/host/src/adapter/**`.
2. **Resumption Filter:** The `follow` adapter wraps `typertGateway.stream` and filters out snapshot frames where `seq <= afterSeq`.
3. **Packaging:** Deployments build with `pnpm -F @remora/host pack` to produce a standalone tarball for `dsh plugin add`.
