## Goal

Make `pnpm run conformance:check -- --strict` fail on placeholder vectors and on files with too few cases, and add a non-required CI job for it. Today 27 of 33 vector files are placeholders (`"status": "scaffold"`).

## Inputs

- docs/SWARM.md (whole file)
- AGENTS.md
- conformance/README.md
- conformance/schema/vector-file.schema.json
- scripts/check-conformance.mjs

## Deliverables

- `--strict` flag: fail when any case `input.status === "scaffold"`, or any case name matches `/placeholder|scaffold/i`, or a file has fewer cases than the minimums below.
- Minimums: every `crypto/*` file ≥ 3 cases including ≥ 1 `error` case (Cacophony file exempt: it is external and complete); every `rcp/methods/*` file ≥ 2 valid + ≥ 1 invalid; `rcp/envelope.json`, `rcp/limits.json`, `rcp/session-events.json`, `relay/*` ≥ 5 cases each with ≥ 1 error case.
- Print a per-file summary and a total count of violations.
- CI job `conformance-strict` with `continue-on-error: true` (P7-V3 removes it).

## Acceptance

- [ ] `pnpm run conformance:check` (non-strict) still passes on main.
- [ ] `pnpm run conformance:check -- --strict` fails on main and lists at least the 27 known placeholder files (paste the count).

## Evidence rules

- Follow docs/SWARM.md §1 and §7: red CI run first, then green; both links in the PR and the handoff.
- Anything needing a phone, cloud account, secret, or signing key stays unticked with `OWNER-PENDING`.

## Constraints

- No new dependencies.

## Stop and report

- See docs/SWARM.md §6.

## Verify

```sh
pnpm run conformance:check
pnpm run conformance:check -- --strict   # expected: FAIL today
```
