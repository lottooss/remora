## Goal

Add `node scripts/check-no-stubs.mjs` that fails when production source contains stub markers, so placeholders cannot be reported as finished features.

## Inputs

- docs/SWARM.md (whole file)
- AGENTS.md
- Audit list in docs/SWARM.md §0

## Deliverables

- Scan: `packages/*/src/**/*.ts` (excluding `packages/testkit`), `apps/relay/src/**`, `apps/cli/src/**`, `apps/android/**/src/main/**/*.kt`.
- Fail on: `TODO`, `FIXME`, `XXX`; the word `placeholder` in string literals (ignore Compose `placeholder = {` parameters by matching only inside `"..."` or `'...'`); `PlaceholderScreen(` in any file outside `core/ui`; `(ctx as any)` and `as unknown as { on(`; `globalThis.koffi`; `not implemented`.
- `scripts/gates.allow.json`: explicit allowlist entries `{ file, pattern, reason, expires }` (empty to start; entries require owner approval).
- Root script `check:no-stubs`; CI job `no-stubs` with `continue-on-error: true` (P7-V3 removes it).

## Acceptance

- [ ] On main the scanner fails and its output includes at least: `RemoraMessagingService.kt` TODO, `RemoraRoot.kt` "Unlock (placeholder)", `HostsScreen.kt`, `DiagnosticsScreen.kt`, `packages/host/src/index.ts` `(ctx as any)`, `keep-awake-win32.ts` `globalThis.koffi` (paste output).
- [ ] The scanner has its own unit test with fixture files for every pattern.

## Evidence rules

- Follow docs/SWARM.md §1 and §7: red CI run first, then green; both links in the PR and the handoff.
- Anything needing a phone, cloud account, secret, or signing key stays unticked with `OWNER-PENDING`.
