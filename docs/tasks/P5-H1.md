## Goal

Turn dsh and AnswerBridge activity into timely, deduplicated, end-to-end encrypted push notifications per device, respecting preferences and presence (blueprint §8.10).

## Inputs

Blueprint §8.10, RCP/1 §10, Crypto/1 §8, RLY/1 §5 `push`.

## Deliverables

- Triggers: pending approval/question (from AnswerBridge), `turn/end` for sessions the device opened in the last 24 h, `agent/error`.
- Presence-aware suppression (connected + foregrounded device gets in-band events only), collapse keys, rate limiting (≤ 1 per session per 30 s for turn notifications).
- Per-device prefs (`notify.prefs.get/set`) persisted in the storage domain.
- Payload builder (≤ 2 KiB, human text never includes secrets; command previews truncated to 80 chars) + `@remora/crypto` push sealing.
- Tests with a fake relay link: every trigger, suppression, prefs, sealing round-trip with the testkit.

## Acceptance

- [ ] e2e: approval while the testkit device is disconnected produces exactly one `push` frame with decryptable content.
- [ ] No notification is sent for a device that disabled that kind.

## Verify

```sh
pnpm -F @remora/host test && pnpm test:e2e -t notify
```
