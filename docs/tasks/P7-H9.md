## Goal

In real dsh the first gateway call can fail with `gateway/service-unavailable` because `sessionController` is still starting (recorded in packages/host/test/fixtures/dsh-0.1.5-rc.3/report.json). Retry exactly that error with a bounded backoff.

## Inputs

- docs/SWARM.md (whole file)
- AGENTS.md
- spikes/p0-s1-dsh-adapter/src/index.js `invokeReady` (working pattern)
- packages/host/test/fixtures/dsh-0.1.5-rc.3/report.json (`errors`)

## Deliverables

- `invoke` and `stream` wrappers retry only `code === 'gateway/service-unavailable'`, every 250 ms, up to a configurable 30 s deadline (constructor option), honoring the caller's AbortSignal; all other errors propagate immediately.
- Tests with an injected clock: retries then succeeds; gives up at the deadline with the original error; abort stops retries; non-matching errors are not retried.
