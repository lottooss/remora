## Goal

Serve RCP/1 §6: follow registered workspaces, browse and create directories inside the allowlisted roots, and start new sessions remotely — all through the Policy Guard.

## Inputs

RCP/1 §6, blueprint §11.6, dsh-integration §4 (workspace controller, directory picker), P3-H2 `PolicyGuard`.

## Deliverables

- `workspaces.follow` (from `workspace/follow`, with `remoteAllowed` computed per root), `workspaces.create`, `fs.browse` (roots listing when `path` absent; `directoryPicker/list` otherwise), `fs.mkdir`, `sessions.create` (`{ id }` or `{ path }`).
- Idempotency cache by `requestId`.
- Tests: creation inside/outside roots, `allowRemoteSessionStart: false`, existing outside-root workspace by id, hidden/system folders, long names, name validation for mkdir.

## Acceptance

- [ ] e2e: the testkit device browses a root, creates a folder, starts a session there, prompts it.
- [ ] Every path in requests and results is canonical; nothing outside roots is listed.

## Stop and report

- `directoryPicker/list` cannot be pointed at arbitrary roots (then list via `ctx.fs` in the adapter and document).

## Verify

```sh
pnpm -F @remora/host test && pnpm test:e2e -t workspaces
```
