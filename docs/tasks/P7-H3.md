## Goal

`enrollHost()` exists but production code never calls it; only tests do. The real host is therefore unknown to the relay and fails authentication. Enroll on startup (idempotent), then connect.

## Inputs

- docs/SWARM.md (whole file)
- AGENTS.md
- docs/specs/relay-v1.md §4.1
- packages/host/src/relay/index.ts `enrollHost`
- docs/runbooks/operations.md (how the owner supplies `REMORA_RELAY_ENROLL_SECRET`)

## Deliverables

- Read the secret through `ctx.credentials` using the key named by `config.enrollSecretKey` (resolved from launch env / credentials store / `.env`). Missing → throw a `RemoraConfigError` naming the key and the file to put it in.
- Call `enrollHost` before `relay.start()`; remember success in the identity record (`enrolledRelayOrigin`) so later starts skip it; on 401 log an actionable error and do not start the relay loop; retry network errors with backoff.
- Log at info: `remora: relay ready (host <first 6 chars of id>)` when the relay link reaches `ready`.

## Acceptance

- [ ] Unit tests with a fake relay HTTP server: enrolls once; skips when already enrolled for that origin; 401 path; missing-secret path.
- [ ] CI `real-dsh` fully green on ubuntu and windows (paste run link).
