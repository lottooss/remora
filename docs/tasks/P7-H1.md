## Goal

Fix the startup crash. `apply()` currently declares `inject: []` and reads `(ctx as any).typertGateway`, which Cordis 4 forbids, so dsh exits on boot. The plugin must declare its required services, handle the optional web connection correctly, and be tested through `apply()` on a real Cordis context.

## Inputs

- docs/SWARM.md (whole file)
- AGENTS.md
- packages/host/src/index.ts (whole file)
- spikes/p0-s1-dsh-adapter/src/index.js — a plugin that DID load in real dsh: `inject = ['typertGateway', 'connection', 'credentials', 'storage']`
- Cordis 4 types: node_modules/@deepseek-ai/cordis/lib/types/registry.d.ts — `inject` lists REQUIRED services only; for an optional service use `ctx.inject(['connection'], (ctx) => { … })` inside apply
- docs/upstream/dsh-integration.md §3, §4, §7

## Deliverables

- Commit 1 (red): `packages/host/test/apply.test.ts` creates a real `@deepseek-ai/cordis` root `Context`, provides minimal fake services named `typertGateway`, `credentials`, `storage` (fakes of the dsh side only), mounts the host plugin with a valid config via `ctx.plugin(...)`, and asserts: no error, the logger received `remora: host started`, and disposal completes within 2 s. A second case mounts without `typertGateway` and asserts the plugin is pending (not started, not crashed). On current main case 1 fails with the inject error.
- Commit 2: `export const inject = ['typertGateway', 'credentials', 'storage']`; remove every `(ctx as any)` and `as unknown as { on(` cast (use `import type {} from '@deepseek-ai/dsh-api-gateway'` etc. for declaration merging; those imports are type-only dev dependencies pinned to `upstream.lock.json`); register the management routes inside `ctx.inject(['connection'], …)`; remove the silent `if (gateway)` branch (the gateway is now guaranteed).
- Register every listener with `ctx.on` / every resource with `ctx.effect` (no untyped `on`).
