## Goal

The core remote experience: hosts and sessions list, a conversation screen that renders history and the live stream smoothly, a composer that queues or steers, stop, model selection, and correct resume after reconnects.

## Inputs

RCP/1 §5; blueprint §10.3, §10.6, §11.2–§11.3; recorded RCP transcripts from `@remora/testkit` (`packages/testkit/transcripts/*.jsonl`) for development without a host.

## Deliverables

- `:core:data`: Room entities for sessions and events (bounded 2,000 per session), `SyncEngine` (open/close follows by visibility, `afterSeq` resume, reset handling, live-frame overlay that retires on settlement), repositories.
- `:feature:sessions`: grouped by workspace, status dots from `sessions.control`, search, pull-to-refresh.
- `:feature:conversation`: transcript (markdown, code blocks with copy, collapsible tool cards with truncated previews and "load more" via `sessions.toolOutput`), live streaming bubble, composer (queue/steer, idempotent send with `requestId` and retry), stop button, model picker, "load older" paging, offline banner and disabled actions.
- Compose UI tests for key states with fake repositories.

## Acceptance

- [ ] 10,000-event session scrolls smoothly (no jank in a profileable build on the owner's phone).
- [ ] Airplane mode on/off mid-stream → transcript converges with no duplicates or gaps.
- [ ] A send retried after a timeout runs once on the host (same `requestId`).

## Constraints

- No mutating actions while disconnected.

## Stop and report

- RCP lacks data required by the UI (propose an additive spec change).

cd apps/android && ./gradlew testDebugUnitTest assembleDebug
