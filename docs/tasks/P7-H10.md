## Goal

`packages/host/src/interaction/dsh-waterfalls.ts` is the approval/question bridge (ADR-0008) and no other packet covers it. It has three defects found in review on 2026-10-01:

1. Six `(ctx as any)` casts and `req: any` (flagged by `check-no-stubs`).
2. The startup self-check dispatches a fake `approval/request` (tool `remora-selfcheck-probe`, fake agent) through dsh's **real** waterfall. Its ordinary sentinel listener calls `next()`, so every other listener — including api-remotes, which forwards approvals to connected browsers — can receive the fake request. A connected PC GUI could show a bogus approval card.
3. `findPreview` reads tool arguments from guessed field shapes. In real dsh `tool/call` data is `{ turn, step, callId, name, arguments: string }` — `arguments` is a **JSON string** (`.upstream/deepseek-harness/packages/core/session/src/types.ts` ~line 341). The recorded fixtures under `packages/host/test/fixtures/dsh-0.1.5-rc.3/` contain **no** tool-call or approval events at all, so neither previews nor `event-map.ts` tool mapping were ever checked against real data.

## Deliverables

- Record real fixtures with the pinned dsh and a scripted mock LLM (`@deepseek-ai/dsh-llm-mock-server` via `DEEPSEEK_BASE_URL`, or the P0-S2 spike's approach): a session where the model calls a bash tool that requires approval, plus `ask_user_question`. Save `follow-tool-approval.jsonl` (durable `tool/call`, `approval/asked`, `approval/decided`, `tool/result` events) and the raw `ApprovalRequestEvent` / question request payloads (agent identity reduced to `{ id }`) under `packages/host/test/fixtures/dsh-0.1.5-rc.3/`. Document the procedure in `docs/upstream/dsh-integration.md` §9.
- Type the listeners with the real event declarations (`import type {} from '@deepseek-ai/dsh-user-approval'`, `…/dsh-user-questions`; type-only dev dependencies pinned to `upstream.lock.json`). No `as any`, no `req: any`.
- Self-check that cannot leak: the probe listener registered with `prepend: true` records the call and **returns a result without calling `next()`**, so no other listener ever sees the probe; the check passes only if the prepend probe ran and no ordinary listener ran first. Dispose both probes in `finally`.
- `findPreview`: parse `arguments` as JSON; for shell tools show the command (`command` field), otherwise a compact one-line summary; `preview.json` is the parsed-and-re-serialized arguments, truncated per RCP/1 §8 limits; on malformed JSON fall back to the raw string. `argsDigest` must stay consistent with Crypto/1 §7.
- Confirm (and test) that `race.ts` withdraws the PC chain by aborting the derived signal it substituted on the request, as ADR-0008 requires.
- Preserve the real Session receiver when reading its journal. Classify approval risk from the full arguments of the matching `tool/call`, before preview truncation. Missing, malformed, or mismatched call metadata must require high-risk authorization rather than silently becoming a normal-risk shell approval. These corrections are part of the Integrator's review of the real-preview integration; no wire contract changes.
- Wire the configured Policy Guard and approval timeout into the bridge from the real `apply()` composition root. Await the startup self-check and fail plugin startup on false or error. Test this through real Cordis so helper-only tests cannot conceal disabled production enforcement.
