## Goal

`apps/relay/test/push.test.ts` › "dispatches push message from host to device with byte-identical ciphertext" fails intermittently with `expected 2 to be 1` at `expect(capturedFcmRequests.length).toBe(1)` (CI run 36887322615, attempt 1; passed on re-run). An earlier test in the file disconnects a host, which arms the host-offline Durable Object alarm with a short `HOST_OFFLINE_ALERT_MS`. When that alarm fires inside the next test, the relay sends a metadata-only `host_offline` FCM message, and the test sees two captured requests.

The relay behaviour is correct (RLY/1 §8). The test isolation is not.

## Deliverables

- Make each push test deterministic: either reset `capturedFcmRequests` at the start of each test and assert only on requests that belong to the test (e.g. filter by `data.ct === testCiphertext`, with a separate explicit assertion for any expected `host_offline` message), or drive the alarm explicitly with `runDurableObjectAlarm` instead of real timers.
- The host-offline alarm test keeps asserting that exactly one `host_offline` push is sent, and only after the delay.
