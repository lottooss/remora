## Goal

Replace the fake-gateway e2e with scenarios against real dsh (P7-G1 environment), a local relay, a scripted mock LLM, and the testkit `FakeDevice`. This is the test that proves the host works.

## Inputs

- docs/SWARM.md (whole file)
- AGENTS.md
- tests/real-dsh/boot.spec.ts
- packages/testkit/src (FakeDevice)
- spikes/p0-s1-dsh-adapter (how prompts and follow were driven for real)
- npm `@deepseek-ai/dsh-llm-mock-server` + `DEEPSEEK_BASE_URL`
- docs/specs/rcp-v1.md

## Deliverables

- Pairing through the real management page: read the `dsh web:` launch URL with token from stdout, exchange it for the cookie, POST "pair", read the QR payload from the page, `FakeDevice` pairs, test confirms the SAS via POST.
- Scenarios: sessions.list; sessions.create in a temp root; prompt → live deltas → settled `assistant.message`; cancel a long turn; approval: mock LLM calls a tool requiring approval, device receives it on `interaction.follow`, answers `allowed-once`, tool runs; question via `ask_user_question`; files.read and diffs.status after the mock agent edits a file; host restart → device reconnects without re-pairing.
- Script `test:real-dsh:e2e`; CI job `real-dsh-e2e` (non-required until P7-V3).
- Delete or clearly rename the old `tests/e2e` specs that use `useRealDsh: false` to `tests/component/` so nobody mistakes them for e2e.

## Acceptance

- [ ] Every scenario passes on ubuntu CI (paste link); any scenario that cannot pass is reported as a bug issue against the owning packet, not skipped.
- [ ] No scenario mocks dsh, the host, or the relay.

## Evidence rules

- Follow docs/SWARM.md §1 and §7: red CI run first, then green; both links in the PR and the handoff.
- Anything needing a phone, cloud account, secret, or signing key stays unticked with `OWNER-PENDING`.
