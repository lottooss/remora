## Goal

Validate the relay mechanics of [RLY/1](../specs/relay-v1.md) on workerd: one `AccountHub` object, hibernating sockets, auto-response keepalives, routing binary frames between two authenticated endpoints, newest-wins replacement, alarms, and request accounting.

## Inputs

[ADR-0002](../adr/0002-cloudflare-e2e-relay.md), [RLY/1](../specs/relay-v1.md), Cloudflare docs: Durable Objects WebSocket hibernation, `setWebSocketAutoResponse`, SQLite storage API, alarms, pricing (free plan).

## Deliverables

- `spikes/p0-s3-relay/`: Worker + DO prototype (TypeScript, `wrangler dev`) with tag-based `getWebSockets(id)`, `serializeAttachment`, a two-client Node script that exchanges 10,000 frames of 1–64 KiB and verifies order and integrity.
- Measurements: round-trip latency locally; whether auto-response pongs wake the object; attachment survival across hibernation; behavior on `wrangler dev` restart (disconnect codes); alarm firing after a host disconnect.
- `docs/spikes/P0-S3.md`: findings, the billed-request model for a streaming hour (with the math), and any spec changes needed (e.g. frame size, ping interval).

## Acceptance

- [ ] Ordered, lossless delivery for the full test run; frames > 64 KiB rejected.
- [ ] Hibernation observed (object evicted while sockets stay open) and resumed correctly.
- [ ] Newest-wins replacement closes the old socket with 4409.
- [ ] Optional (owner action): one deploy to the owner's account to confirm free-plan availability of SQLite-backed DOs; skip if the owner is unavailable and say so.

## Constraints

- No secrets committed; `wrangler login` is an owner action.

## Stop and report

- Any free-plan limitation that breaks the single-object design.

cd spikes/p0-s3-relay && pnpm install && pnpm exec wrangler dev   # then: node scripts/two-clients.mjs
