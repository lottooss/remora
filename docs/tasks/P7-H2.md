## Goal

The host generates new keys on every start (`createHostIdentity()` with no stored material), so every restart breaks every pairing. Load the identity from dsh credentials, creating it once.

## Inputs

- docs/SWARM.md (whole file)
- AGENTS.md
- docs/specs/crypto-v1.md §3 (record `remora/host-identity`), §9
- spikes/p0-s1-dsh-adapter/src/index.js credentials probe: `ctx.credentials.modifyRecord(key, async () => ({ kind, payload }))`, `readRecord`, `describeRecord`, `deleteRecord`; key from `credentialKey(owner, id)` (`@deepseek-ai/dsh-credentials`, type/runtime available inside dsh)
- .upstream/deepseek-harness/packages/credentials/credentials/README.md

## Deliverables

- `loadOrCreateHostIdentity(credentials)`: reads record `remora/host-identity`; if absent, generates relay Ed25519 seed + Noise X25519 key, writes them with `modifyRecord` (atomic create-if-absent), returns the identity. Secrets never logged.
- If apply must await it: start the host inside an async effect (check whether Cordis 4 accepts an async `apply`; if not, run the async startup inside `ctx.effect` and log failures loudly).
- apply.test.ts: fake credentials store; mounting twice yields the same host id.
