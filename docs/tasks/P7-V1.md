## Goal

Replace placeholder crypto vectors (`noise-remora.json` is a scaffold; others have 1–2 cases) with generated vectors that both implementations run.

## Inputs

- docs/SWARM.md (whole file)
- AGENTS.md
- docs/specs/crypto-v1.md §11
- packages/crypto/src
- apps/android/core/crypto/src/test/.../CryptoConformanceTest.kt

## Deliverables

- `packages/crypto/scripts/gen-vectors.ts` generating every crypto file from fixed test keys, meeting P7-G2 minimums: noise-remora (both purposes, prologue, channel records, tamper → error), endpoint-id, relay-auth, pairing (QR parse incl. expired/invalid, pairPsk, SAS), approval (digest, canonical message, DER incl. a high-S signature, wrong-digest error), push (fixed nonce, AAD, tamper error).
- TS tests load every crypto vector file; Kotlin `CryptoConformanceTest` loads every crypto vector file (not a hand-picked subset).

## Acceptance

- [ ] `pnpm run conformance:check -- --strict` passes for `crypto/*`.
- [ ] Both test suites iterate all cases of all crypto files (assert count > 0 per file).

## Evidence rules

- Follow docs/SWARM.md §1 and §7: red CI run first, then green; both links in the PR and the handoff.
- Anything needing a phone, cloud account, secret, or signing key stays unticked with `OWNER-PENDING`.

## Stop and report

- See docs/SWARM.md §6.

pnpm run conformance:check -- --strict
pnpm -F @remora/crypto test
cd apps/android && ./gradlew :core:crypto:test
