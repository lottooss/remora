## Goal

Connect Android feature screens to the real pairing, transport, session, interaction,
files and settings services. Keep host identity explicit through navigation and every
mutating callback, and own foreground connection lifetimes in one application coordinator.

## Inputs

- AGENTS.md and docs/SWARM.md
- docs/blueprint.md §1–§7, §10
- docs/specs/rcp-v1.md and docs/specs/crypto-v1.md
- P7-A1 through P7-A7 and their handoffs

## Deliverables

- Hilt application ViewModel and one isolated runtime per paired host.
- Real feature dependencies, stream visibility lifetimes, pairing callbacks, notification
  routes containing host identity, and truthful disconnected/error states.
- Approval preview digest recomputation and structured question input matching the
  current TypeScript implementation; discrepancies in frozen specs recorded explicitly.
- An implementation handoff distinguishing deferred verification from completion evidence.

## Acceptance

- [ ] Android assembly and JVM tests pass on the combined implementation.
- [ ] Installed app pairs, follows live sessions, sends prompts and answers requests.
- [ ] Switching/removing hosts during biometric signing cannot dispatch to another host.
- [ ] Backgrounding closes sockets after the grace period; foregrounding restores streams.
- [ ] Physical biometric, QR, Firebase and process-death checks have owner evidence.
- [ ] Frozen crypto specification conflicts have a coordinated contract resolution.

## Scheduling amendment (2026-10-04)

The owner explicitly requested implementation first and deferred test waits. P7-A1–A8
are therefore being implemented in parallel on an integration branch, without treating
unfinished dependency verification as a coding barrier. This does not claim any acceptance
gate passed, authorize merging unverified work, or permit silent changes to frozen contracts.
The two approved H6 protected-file changes remain the only protected-file approvals.

The Integrator also authorizes the supporting runtime fixes discovered while composing the
Android client: `packages/host/src/adapter/**`, `packages/host/src/index.ts` activity wiring,
`packages/host/src/rcp/methods/devices.ts` P-256 key-format normalization, their existing fixtures,
and corresponding host README/upstream seam documentation. They preserve the wire method shapes
and bring streaming and rotation behavior into agreement with the existing producer/consumer code.
