## Goal

Make one authoritative RCP method list. The host registers methods the spec does not define (`sessions.get`, `diffs.get`, `diffs.hunk`, `files.readBytes`, `workspaces.list`), the app calls `workspaces.list`, and the spec defines methods nobody implements (`devices.self`, `devices.unpair`, `devices.rotateApprovalKey` on the host; `interaction.follow`, `sessions.control`, `workspaces.follow`, `notify.prefs.*` in the app).

## Inputs

- docs/SWARM.md (whole file)
- AGENTS.md
- docs/specs/rcp-v1.md §4–§11
- packages/protocol/src (method registry)
- packages/host/src/rcp/methods/*.ts (registerMethod calls)
- apps/android: `grep -rhoE "\"[a-z]+\.[a-zA-Z.]+\"" --include=*.kt` in src/main

## Deliverables

- For each extra host method: either add it to the spec (additive, with types and a changelog line) or list it for removal in P7-H7. Prefer removal unless the app needs it.
- `@remora/protocol` exports `RCP_METHODS` (name, kind, mutating) exactly equal to spec §11; a test parses the spec table and asserts equality.
- Export the same list as `conformance/vectors/rcp/method-list.json` (generated) so Kotlin can assert against it in P7-A5.

## Acceptance

- [ ] Spec §11 table, `RCP_METHODS`, and `method-list.json` are identical (test).
- [ ] A written decision table (in the PR) for every mismatched method.

## Evidence rules

- Follow docs/SWARM.md §1 and §7: red CI run first, then green; both links in the PR and the handoff.
- Anything needing a phone, cloud account, secret, or signing key stays unticked with `OWNER-PENDING`.

## Constraints

- Additive changes only; follow AGENTS.md §6.

## Stop and report

- See docs/SWARM.md §6.
