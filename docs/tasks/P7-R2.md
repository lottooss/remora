## Goal

RLY/1 §3 requires closing a connection that has not authenticated within 10 s with close code 4408. `AccountHub` uses one Durable Object alarm for two purposes: the authentication timeout (armed on connect via `armMinAlarm(now + authTimeoutMs())`) and host-offline alerts (RLY/1 §8). Two code paths delete that shared alarm without re-arming it for sockets that are still waiting to authenticate:

1. `cancelOfflineTask()` calls `deleteAlarm()` whenever no offline task remains (for example, when a host reconnects).
2. `alarm()` ends with `else await this.ctx.storage.deleteAlarm()` when no offline task is pending, even if an unauthenticated socket connected after this alarm was scheduled and is not yet due.

Either way, an unauthenticated socket can stay open indefinitely, hibernating and costing nothing to an attacker. `onAuth` still rejects a late `auth` frame, but the socket is never closed. Found by the P7-R1 worker and confirmed by the integrator.

## Deliverables

- One function computes the next alarm time as the minimum of: the earliest `connectedAt + authTimeoutMs()` over unauthenticated sockets (from attachments), and the earliest due offline task. Both `cancelOfflineTask()` and the end of `alarm()` call it, and it deletes the alarm only when nothing is pending.
- Tests in workerd:
  - Connect a socket and never authenticate, then trigger an offline-task cancellation (host connects and disconnects, then reconnects). Running the alarm at `connectedAt + 10 s` must still close the socket with 4408.
  - An alarm that fires for an offline task while another socket is unauthenticated and not yet due re-arms for that socket's deadline.
