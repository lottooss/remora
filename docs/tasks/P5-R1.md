## Goal

Implement [RLY/1 §8](../specs/relay-v1.md#8-push): FCM HTTP v1 data messages for host-provided ciphertext, FCM token registration, token cleanup, and the relay-generated host-offline alert.

## Inputs

RLY/1 §5 and §8, ADR-0006, Crypto/1 §8, blueprint §9.5–§9.6; Firebase docs: FCM HTTP v1 `messages:send`, service-account OAuth2 JWT (RS256, scope `https://www.googleapis.com/auth/firebase.messaging`).

## Deliverables

- `push.token` handling (with `hostOffline` preference), `push` → FCM with `collapse_key`, priority, TTL; per-device `push.result`; token cleanup on `UNREGISTERED`/`INVALID_ARGUMENT`.
- OAuth token minting with WebCrypto (`RSASSA-PKCS1-v1_5` + SHA-256) from `FCM_SERVICE_ACCOUNT_JSON`, cached in `kv`.
- DO alarm for host offline (arm on last socket close, cancel on reconnect, fire → metadata-only push).
- `FCM_ENDPOINT` override var for tests; a fake FCM server in tests.

## Acceptance

- [ ] Workers tests: token registration, push fan-out, error mapping, token cleanup, alarm arm/cancel/fire, payload passthrough is byte-identical.
- [ ] Owner action documented: creating the service account and `wrangler secret put FCM_SERVICE_ACCOUNT_JSON`.

## Constraints

- The relay never decrypts or inspects `ct` beyond its length.
