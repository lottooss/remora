## Goal

Choose the concrete Windows mechanisms for ADR-0009: a per-user logon start that needs no elevation and shows no window, a supervisor that restarts dsh, and a keep-awake request held from inside the dsh process. Answers Q9.

## Inputs

[ADR-0009](../adr/0009-always-on-host.md), [blueprint §8.11](../blueprint.md#811-keep-awake). Windows: `schtasks /Create /SC ONLOGON`, PowerShell `Register-ScheduledTask` with `New-ScheduledTaskTrigger -AtLogOn -User $env:USERNAME`, `HKCU\...\Run`, `conhost.exe --headless`, `SetThreadExecutionState`, `powercfg /requests`.

## Deliverables

- `spikes/p0-s6-always-on/`: scripts that (1) try each registration method as a standard user and report success/failure, (2) start a dummy Node process hidden at logon, (3) hold `ES_CONTINUOUS | ES_SYSTEM_REQUIRED` via `koffi` from a plugin-like module and via a helper process, verified with `powercfg /requests`, and release it.
- `docs/spikes/P0-S6.md`: matrix of methods × (needs admin? window flash? restart on failure? runs after sleep/resume?), chosen design, and the power-settings guidance for the operations runbook.

## Acceptance

- [ ] A method that needs no elevation and shows no window is identified and demonstrated across a sign-out/sign-in.
- [ ] Keep-awake request visible in `powercfg /requests` while held and gone after release or process exit.
- [ ] Whether `koffi` resolves from an out-of-tree bundle inside dsh is answered.

## Constraints

- Do not change system power settings; do not leave scheduled tasks or Run keys behind (provide cleanup script and run it).

## Stop and report

- Every logon method requires elevation on the owner's machine.

## Verify

`spikes/p0-s6-always-on/cleanup.ps1` leaves no residue (`schtasks /Query`, `reg query` shown in findings).
