## Goal

Make the three v1 specs internally consistent and machine-checkable: define one JSON format for cross-language test vectors, scaffold the directories, and produce a review list of every ambiguity the spikes or implementers will hit.

## Inputs

[blueprint](../blueprint.md), [RCP/1](../specs/rcp-v1.md), [RLY/1](../specs/relay-v1.md), [Crypto/1](../specs/crypto-v1.md), [threat model](../specs/threat-model.md), [conformance/README.md](../../conformance/README.md).

## Deliverables

- `conformance/README.md` finalized: vector file schema (`{ "suite", "version", "cases": [{ "name", "input", "expect" | "error" }] }`), naming, how TS (Vitest) and Kotlin (JUnit) load them, how new vectors are added.
- `conformance/schema/vector-file.schema.json` (JSON Schema) and a check in `pnpm run conformance:check` that validates every vector file against it.
- Empty-but-valid vector files for every file named in the specs' "Conformance vectors" sections.
- `docs/specs/REVIEW.md`: numbered list of ambiguities/inconsistencies with a proposed resolution each (e.g. exact JSON field order irrelevance, UTF-8 offset alignment rules, snapshot size packing rule).

## Acceptance

- [ ] Every vector file path mentioned in any spec exists and validates against the schema.
- [ ] `pnpm run conformance:check` passes locally and in CI.
- [ ] `docs/specs/REVIEW.md` has zero unowned items (each names the task that resolves it).

## Constraints

- Do not change normative behavior in specs without recording it in REVIEW.md; P0-A2 applies accepted changes.

## Stop and report

- A spec contradiction that changes wire bytes or security properties.

## Verify

```sh
pnpm install && pnpm run conformance:check
```
