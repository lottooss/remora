## Goal

Serve RCP/1 §9: read-only file browsing and viewing through `workspaceFiles/*`, change notifications, and diffs from a hardened git invocation with a session-derived fallback.

## Inputs

RCP/1 §9, blueprint §8.8, §11.7, threat model T12 and T17, dsh-integration §4 (workspace files).

## Deliverables

- `files.list/stat/read/changes` via the gateway with Policy Guard containment (session root ∪ roots) and the 5 MiB read cap.
- `adapter/git.ts`: spawn `git` with `-c core.fsmonitor=false -c core.hooksPath=<empty temp dir> --no-optional-locks`, `--no-ext-diff --no-textconv --no-color`, `cwd` = canonical workspace root, 5 s timeout, 1 MiB output cap, `-z` parsing; `diffs.status` and `diffs.file` (hunk paging to stay ≤ 48 KiB).
- Fallback when not a repository or git is missing: files touched by write/edit tool calls in the session log.
- Tests with fixture repositories, including hostile config (`core.fsmonitor`, `diff.external`, `filter.*.textconv`) that must not execute, renames, binary files, huge diffs.

## Acceptance

- [ ] Hostile repository config never executes (canary file not created).
- [ ] e2e: after the mock agent edits a file, `diffs.status` and `diffs.file` show the change.

## Stop and report

- `workspaceFiles` refuses reads the guard allows or vice versa in ways that matter.

## Verify

pnpm -F @remora/host test && pnpm test:e2e -t files
