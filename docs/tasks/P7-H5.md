## Goal

Push notifications for finished and failed turns never fire because the handlers assume wrong shapes. Real dsh: `session/event` is emitted as `(session: Session, event: SessionEvent)`; `agent/error` payload is `{ agent, turn, step, error }` (no `sessionId`; the session id is `agent.id`); `agent/status` is `{ agent, status }`.

## Inputs

- docs/SWARM.md (whole file)
- AGENTS.md
- .upstream/deepseek-harness/packages/core/session/src/index.ts line ~72 (`session/event` signature)
- .upstream/deepseek-harness/packages/core/agent/src/runtime-types.ts line ~403 (`agent/error`)
- packages/host/test/fixtures/dsh-0.1.5-rc.3/follow-*.jsonl (real `turn/end` events)
- blueprint §8.10

## Deliverables

- Handlers typed against the real signatures (type-only imports), mapping `turn/end` to `notifyTurnDone(session.id, title)` and `agent/error` to `notifyTurnError(agent.id, …)`.
- Implement `isDeviceForegrounded` from real presence (device has an open channel and an active `sessions.follow` for that session) instead of the constant `false`.
- Apply-harness tests emit events with the exact real shapes (`ctx.emit('session/event', session, event)`), using a `turn/end` taken verbatim from the fixture.
