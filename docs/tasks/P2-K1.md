## Goal

A phone that can pair with a host and hold a live, encrypted RCP connection: QR scanning, key generation and storage, relay client, secure channel (initiator), RCP client, host records.

## Inputs

Crypto/1 §3, §5, §6, §9; RLY/1; RCP/1 §2, §4, §7; blueprint §10.3–§10.4, §11.1–§11.2; `docs/spikes/P0-S5.md`.

## Deliverables

- `:core:security`: Tink keyset manager (`remora_master_v1`), per-host key material store, Keystore approval key creation (per P0-S5), wipe on unpair.
- `:core:transport`: `RelayClient` (OkHttp WebSocket, auth, backoff with network callbacks, ping), `SecureChannel` (initiator using `:core:crypto`), `RcpClient` (requests with timeouts, stream flows, cancellation), `ConnectionManager` (foreground-only lifecycle, per-host).
- `:feature:pairing`: CameraX + ML Kit QR scan, QR validation, enrollment call, SAS screen ("Confirm 482 193 on your PC"), success/failure states, pairing with a second host.
- `:core:data`: `HostRepository` (Room: hosts), connection state exposed as `StateFlow`.

## Acceptance

- [ ] Pairs with a host running from source (local relay reachable at `http://10.0.2.2:8787` on the emulator in debug builds, deployed relay on a device).
- [ ] After pairing, the app reconnects automatically on foreground and shows host online/offline from presence.
- [ ] Unit tests for transport state machines with a fake WebSocket; no secrets in logs (log-scan test).

## Constraints

- Debug-only cleartext relay allowed via network security config for `10.0.2.2`/`127.0.0.1`; release builds require https.

## Stop and report

- Keystore behavior on the owner's phone contradicts P0-S5.
