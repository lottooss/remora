# Conformance vectors

Cross-language test vectors shared by the TypeScript implementations (`@remora/protocol`, `@remora/crypto`, the relay) and the Kotlin implementations (`:core:protocol`, `:core:crypto`). A construction is implemented correctly only when **both** languages pass **all** vectors for it.

## Layout

```text
conformance/
  schema/vector-file.schema.json   JSON Schema every vector file must satisfy
  vectors/
    crypto/   noise-cacophony-ikpsk2.json, noise-remora.json, endpoint-id.json, relay-auth.json,
              pairing.json, approval.json, push.json
    rcp/      envelope.json, session-events.json, limits.json, methods/<method>.json
    relay/    data-frame.json, control-frames.json, auth.json
  interop/    cross-language handshake runner (P1-K1)
```

## File format

```json
{
  "suite": "crypto/push",
  "version": 1,
  "source": "generated by packages/crypto/scripts/gen-vectors.ts",
  "cases": [
    {
      "name": "seal with fixed nonce",
      "input": { "pushKey": "<hex>", "nonce": "<hex>", "hostId": "h_…", "deviceId": "d_…", "plaintext": "{…}" },
      "expect": { "ct": "<b64u>" }
    },
    {
      "name": "tampered tag is rejected",
      "input": { "pushKey": "<hex>", "hostId": "h_…", "deviceId": "d_…", "ct": "<b64u>" },
      "error": "aead_verification_failed"
    }
  ]
}
```

- Binary values: lowercase hex in vectors unless the spec defines the wire encoding (then use that encoding, e.g. b64u).
- Each case has exactly one of `expect` or `error`. `error` values are stable codes shared by both implementations.
- Keys in vectors are test keys generated for vectors only. Never paste a real key.

## Rules

- Vectors are generated by scripts in the owning TypeScript package, reviewed, and committed; Kotlin never regenerates them.
- Changing an existing case's meaning is a contract change (AGENTS.md §6). Adding cases is always welcome.
- `pnpm run conformance:check` validates every file against the rules in `schema/vector-file.schema.json`.
- External vectors (Cacophony) keep their upstream source URL and license in the file's `source` field.

## How loaders consume vectors

### TypeScript (Vitest)
TypeScript tests read JSON directly via standard ES module imports or `JSON.parse(readFileSync(...))`:
```ts
import vectors from '../../../conformance/vectors/crypto/noise-cacophony-ikpsk2.json' assert { type: 'json' }

describe(vectors.suite, () => {
  for (const c of vectors.cases) {
    it(c.name, () => {
      // execute against @remora/crypto
    })
  }
})
```

### Kotlin (JUnit)
Kotlin modules consume vector files packaged in test resources or read from the repository root:
```kotlin
val vectorStream = javaClass.classLoader.getResourceAsStream("vectors/crypto/approval.json")
val suite = Json.decodeFromString<VectorSuite<ApprovalInput, ApprovalExpect>>(vectorStream.readBytes().decodeToString())

@TestFactory
fun testCases() = suite.cases.map { c ->
  DynamicTest.dynamicTest(c.name) {
    // execute against :core:crypto
  }
}
```

## Adding new vectors
1. Place the new or updated vector file under `conformance/vectors/<area>/<name>.json`.
2. Ensure top-level fields include `suite`, `version`, `source`, and `cases`.
3. Run `pnpm run conformance:check` to validate against `vector-file.schema.json`.
4. Ensure both TypeScript and Kotlin test suites pass the updated vectors.
